# DnD Radio

A synced background-music radio for tabletop sessions. Pick a genre station
(Medieval, Tavern, Celtic, East Asian, Tropical, Dungeon, Royal court,
Egyptian, Kobold):
each has its own playlist, instruments, scale, colours and an animation that
reacts to the music. Everyone tuned in to a station hears the same song at the
same moment.

## Run

```sh
npm install
npm run dev
```

```sh
npm test            # logic tests (Node's built-in runner, Node 22+)
npm run build       # type-check + production build
npm run gen:midi    # regenerate the demo MIDI files in public/midi
```

## Deploy

Pushing to `main` builds and deploys to GitHub Pages via
`.github/workflows/deploy.yml` (it runs the tests first). In the repo settings,
set **Pages → Source** to **GitHub Actions**. The build uses a relative base,
so it works under `https://<user>.github.io/dnd-radio/`.

## The radio

- **Stations**: every song is tagged with the genres it suits. A station's
  playlist is every song with its genre, in a fixed shuffled order, looping
  forever from a shared start (`EPOCH_MS` in `src/radio/schedule.ts`) with a 2 s
  gap between songs. Song durations are stored in the catalogs, so anyone who
  knows the UTC time can work out what's playing and how far in, without a
  server and without downloading anything first.
- **Clock** (`src/radio/clock.ts`): device clocks are often seconds off, so the
  page asks `time.akamai.com` for the time a few times and keeps the fastest
  answer (NTP-style), then runs on `performance.now()`. If that's blocked it
  falls back to the page's own `Date` header (about ±0.5 s), then to the device
  clock. Advanced shows which one is in use and its margin.
- **Scheduling** (`src/music/engine.ts`): notes are scheduled on the Web Audio
  clock, just in time (2 s ahead), mapped to real time with
  `getOutputTimestamp()` (which includes the speaker latency), and the start
  position is decided only after the song and its instruments have loaded. The next song is fetched and scheduled ahead so
  transitions land on the boundary. Changing the scale or instruments re-joins
  the live position.

In headless-browser tests, two listeners whose device clocks disagreed by
several seconds, joining at different times, heard the same notes within a few
milliseconds, on stations of local MIDI, remote MusicXML and remote ABC songs,
and across song changes.

Changing a playlist (adding, removing or re-tagging songs) shifts that
station's schedule for everyone, which is fine as long as everyone loads the
same build.

## Songs

- **Station songs** (`public/midi/`, generated by `scripts/generate-demo-midi.mjs`):
  traditional and public-domain tunes transcribed here. Genres are set in that
  script.
- **Classics and fiddle tunes** (`public/classics.json`, built by
  `scripts/build-classics.mjs`): pieces from the
  [music21 corpus](https://github.com/cuthbertLab/music21), streamed at runtime
  from `raw.githubusercontent.com`, pinned to one commit. Nothing is copied into
  this repo. Includes Joplin, Monteverdi, Bach chorales, Handel, Corelli,
  Schubert, Mozart, Haydn, Trecento madrigals and about 40 jigs, reels,
  hornpipes, strathspeys and clogs from *Ryan's Mammoth Collection* (1883). The
  works are public domain; some encodings are licensed for non-commercial use
  only. To add pieces, edit `PIECES` in the script and run it against a corpus
  checkout (instructions at the top of the file).
- **Your files**: Advanced → Upload takes MIDI, MusicXML (`.musicxml`, `.xml`,
  compressed `.mxl`) and ABC. They play only for you (free play). Modern pop is
  under copyright, so it isn't bundled.

Formats are parsed without extra dependencies: `src/music/musicxml.ts` (with a
tiny XML parser and a `.mxl` unzip built on `DecompressionStream`) and
`src/music/abc.ts`. Single-melody songs (fiddle tunes, lead sheets) get a
generated chord and bass part (`src/music/accompany.ts`) that picks, per half
bar, the triad from the tune's own scale that best fits the melody.

## How it works

- **Genres** (`src/themes.ts`): each picks an instrument set, a colour
  palette, an animation motif (candle motes, hearth embers, leaves, petals,
  bubbles, fog, sparkles, skittering kobolds, desert sand) that reacts to every
  note as it's heard, and optionally a default scale (East Asian: Yo; Egyptian:
  Hijaz; Dungeon and Kobold: harmonic minor) and speed (Kobold: 1.3×).
- **Humanising** (`src/music/humanize.ts`): sequenced notes are given beat
  accents, phrase swells, a few milliseconds of timing looseness, strummed
  chords, slightly detached fast passages, room for repeated notes and ringing
  plucked strings. It's seeded per song, so every listener hears the same
  performance. Fiddle tunes without a tempo mark are paced by their running
  note value, so a reel plays at the same speed whether it's written in 2/4 or
  4/4.
- **Voices** (`src/music/voice.ts`): our own sampler over the FluidR3 General
  MIDI soundfonts. Each note gets an attack shaped for its instrument family
  (bowed and sung notes swell, plucked notes snap), tone that follows velocity
  and opens up during the attack, a few cents of pitch drift, delayed vibrato
  on long notes, sample looping for sustained notes, and a curved release that
  varies note to note and lengthens at phrase ends. Everything plays through a
  room reverb sized per genre (a small tavern, a cavernous dungeon).
- **Loaders** (`src/components/Wave.tsx`): Material-3-style wavy progress and
  loading indicators; the wave's height follows the music and its head sheds
  sparkles.
- **Instrument sets** (`src/music/instruments.ts`): each set is a palette of
  ~10 voices with roles (lead, harmony, pad, accent, bass) plus a percussion
  instrument. Tracks are matched to roles by register (top line = lead, lowest =
  bass), by split lane, and by the track's original General MIDI instrument
  (choir, strings and organs become pads; bells and mallets become accents).
  Instruments aren't reused until the palette runs out. Drums are mapped onto
  the set's percussion instrument (kick, toms and snare only). Any track can be
  overridden individually.
- **Voice splitting** (`src/music/split.ts`): many MIDIs (piano arrangements
  especially) put everything in one track. Polyphonic tracks are split into
  melody / harmony / bass by what is sounding at each note's start: the top
  note is melody, the lowest is bass, inner notes are harmony. This happens
  automatically for files with one or two pitched tracks, and any track can be
  split or merged by hand in the Tracks list.
- **Note sets** (`src/music/noteSets.ts`): target scales. Every note is
  remapped into the chosen scale, relative to the song's key (auto-detected,
  or picked by hand).
  - 7-note scales (Dorian, Phrygian, harmonic minor...) use *degree mapping*:
    a minor-key song keeps its melodic shape and only the altered degrees
    change.
  - Other scales (pentatonics, Hirajoshi, whole tone...) snap each note to the
    nearest scale tone.
- **Playback** (`src/music/engine.ts`): soundfont instruments via `smplr`,
  scheduled on the Web Audio clock. Changing sets, tempo or instruments while
  playing re-schedules from the current position.

## Adding sets

Add an entry to `INSTRUMENT_SETS` or `NOTE_SETS` and it shows up in the UI.
Instruments are General MIDI soundfont names; add new ones to `INSTRUMENTS`.

## Notes

- Instrument samples load from a soundfont CDN the first time they are used.
  If one fails to load, it falls back to piano and shows a message.
- The bundled demo songs are traditional (public domain) tunes. Uploaded files
  are processed in the browser and never leave it.
